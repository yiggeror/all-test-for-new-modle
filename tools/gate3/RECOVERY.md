# Gate 2 原生画面精确重建

本模块是 Gate 3 单命令复现的画面输入层。它只读取仓库
`previews/gate_2/lossless_parts/` 校验拼接出来的四条无损视频，
输出各自第一完整周期的 `330×180×320×3 uint8 RGB` 数组。
它不使用同名手机审看代理、不质损二次转码，也不从工作机读取原始 NPY。

## 做法和校验

1. 固定四条无损 MP4 的 SHA-256（与 Gate 2 发布 `d8796e0` 中的
   分片清单 Git blob `dce7a8d45528948790e75413c02599c3f619f3fa` 对齐）。
2. FFmpeg 解码第一周期的 **原始 YUV420p 平面**。在 1080p 的 6×6
   亮度格和 3×3 色度格分别取中心点，不转换成近似的 RGB。
3. 每季使用自己的冻结色板。每个允许的 RGB 颜色向前按 Gate 2 的
   BT.709 限幅与 6× 最近邻滤镜转换，所得 Y/Cb/Cr 三元组可唯一对应
   回原 RGB。运行时直接查这张表，避免版本间浮点/舍入差异。
   春、夏、秋、冬实用色数分别为 60、59、60、60；夏另一个未用
   色 `(214, 61, 46)` 不加入反查。
4. 输入 MP4、映射表、输出裸 RGB、输出 NPY 文件分别校验 SHA-256，
   并拒绝非映射颜色、缺帧、转码代理或损坏数据。仅在全部通过后
   写入最终 NPY。不会悄悄以近似色替代。

原色板可追溯至 Gate 2 提交的 `previews/gate_2/source/`：
`spring_autumn_source.zip` SHA-256
`9c4e69ee6d6b1944cfc36a3030d24fe1db790ef74a83e9885d3abf6ca8354898`
（包括原运动脚本针对春秋预留的微动色），
`gate2_summer_winter_source_qa.zip` SHA-256
`758fd46755f7ad8259b9ee20e1ba6e6f6472c485b89e67db03110d4b6f1b99ce`。
这两份源 ZIP 仅用于色表溯源，不是复现运行依赖。

## 实证

从仓库分片重组的四条视频，共 1,320 帧全部通过。
与被冻结的原生 NPY 直接逐字节比较，四个文件完全一致。
有损的春手机审看文件被明确拒绝，未产出 NPY。

独立单测可在本文件同目录运行：`python -m unittest -v test_recover_native`。
